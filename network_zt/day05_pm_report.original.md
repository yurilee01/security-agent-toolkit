- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」
  - 답:
  회선 X: 평균 지연 30ms, 지터 1ms
  회선 Y: 평균 지연 26ms, 지터 38ms
  회선 Z: 손실률 40%
- (나) 🔍 평균 지연만 보면 Y 가 더 좋아 보입니다. 화상회의에는 어느 회선이 더 나쁠까요? 왜 그런가요?
  - 쓸 내용: ① 회선 이름 하나 ② 지연 · 지터 숫자를 써서 이유
  - 답:회선 Y가 더 나쁩니다. 평균 지연은 X보다 낮지만 지터가 38ms로 커서 응답 시간이 불규칙합니다. 그래서 화상회의 중 소리나 화면이 끊길 수 있습니다.

  - 쓸 내용: ① 달라진 조건 이름을 모두(PC · 연결 방식 · 대상 주소 · 시각 중) ② 「확정할 수 있다 / 없다」와 이유

- (다) 🔍 무선이 원인인지 확인하려면 무엇을 같게 맞추고, 무엇 하나만 바꿔 다시 재야 하나요?
  - 쓸 내용: ① 같게 맞출 조건 ② 바꿀 조건 하나 ③ 몇 번 재는지
  - 답:

  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(무엇을 알았고 무엇을 더 확인하는지)

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:
  이웃한 응답 시간의 차이를 평균 내어 지터를 구하는 함수이다.
  입력: 응답을 받은 시간 값들의 리스트 got
  리턴: 이웃한 응답 시간 차이의 평균값
```
total = 0
    for i in range(1, len(got)):
        total += abs(got[i] - got[i - 1])
    return total / (len(got) - 1)


- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.

회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?

  회선 C: 부적합 — 손실률이 1%를 초과한다.

## 7교시 · tracert · 진단 · 올리기

### 문제 7-1 · tracert 표에서 느려진 구간 찾기

- (가-1) 표 1 에서 지연이 처음 크게 뛴 구간은 몇 번 홉과 몇 번 홉 사이인가요?

  - 답:
  4번 홉과 5번 홉 사이에서 시간이 6ms에서 48ms로 크게 증가했다.
- (가-2) 그 구간은 우리 회사 쪽일까요, 바깥(통신사)일까요? 근거를 적어 주세요.
  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)
  - 답:
  바깥쪽인 통신사 구간이다.4번 홉은 통신사 중계 장비이고,5번 홉은 해외 연결 지점이기 때문이다.
- (나) 🔍 표 2 의 4번 홉은 60 ms 로 큰데 실제 장애가 아니라고 봅니다. 그 근거는 무엇인가요?
  - 쓸 내용: ① 4번 홉의 뒤 홉 시간 ② 그것이 무엇을 뜻하는지
  - 답:
  4번 홉은 60ms로 크지만,바로 다음 5번 홉은 7ms로 다시 작아지고 6번 홉도 8ms이다.따라서 4번 홉이 실제로 전체 통신을 느리게 만드는 장애라고 단정할 수 없다.해당 장비가 응답을 늦게 했을 가능성도 있다.

#3. SaaS 접속 지연 진단
- 고객 PC에서 SaaS 서버까지 ping 평균은 52ms로, 평소 평균 22ms보다 증가했다.
- 지터 2ms, 손실률 0%이므로 이번 측정에서는 평균 지연 증가가 주요 특징이다.

- 다른 시간대에 ping과 tracert를 다시 측정하고, 필요하면 통신사에 해당 구간의 지연 확인을 요청한다.

4. 최종 결론

회선 품질은 평균 지연뿐 아니라 지터와 손실률도 함께 확인해야 한다. tracert에서 지연이 증가한 구간을 찾을 수 있지만, 한 번의 측정만으로 장애 원인을 단정하지 않고 반복 측정으로 확인해야 한다.
