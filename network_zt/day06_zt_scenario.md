# A사 Zero Trust 적용 방안

## 5대 원칙 적용 방안
- ID: 모든 로그인 경로에 MFA를 적용하고, 비밀번호가 유출되더라도 추가 인증을 통과해야 로그인할 수 있도록 한다.
- Device: 모든 직원 기기를 등록하고 보안 점검을 실시한다. 등록되지 않은 기기나 점검에 실패한 기기는 기본적으로 차단한다.
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다.
- Application: 부서별 업무에 필요한 시스템만 사용할 수 있도록 접근 권한을 나눈다. 영업팀은 정산 포털의 정산 내역을 조회할 수 없도록 한다.
- Policy: 접속 시간, 위치, 기기 상태, MFA 여부, 조회량을 확인해 요청마다 접근을 판단한다. 위험이 높으면 추가 확인하거나 차단한다.

## 판단과 집행
- PDP(결정): 사용자 계정의 재직 여부, MFA 인증, 기기 등록 및 보안 상태, 접속 위치와 시간, 요청 점수를 확인해 허용·추가 확인·거부를 결정한다.
- PEP(집행): 정산 포털과 서버 앞에 두어 PDP의 결정에 따라 요청을 통과시키거나 추가 인증을 요구하거나 차단한다.

## 흐름도
사용자 --요청--> PEP --문의--> PDP
PDP --계정·MFA·기기·위치·시간·조회량 확인--> 접근 결정
PDP --허용 / 추가 확인 / 거부--> PEP
PEP --통과 / 추가 인증 요청 / 차단--> 사용자 또는 시스템

## 최소권한 기준 (목록에 없으면 거부)
- 재무팀: 재무 업무에 필요한 정산 시스템과 정산 내역만 허용한다. 목록에 없는 시스템은 거부한다.
- 영업팀: 영업 업무에 필요한 영업 시스템만 허용한다. 정산 내역 조회는 거부한다.
- 서비스 계정 batch-night: 등록된 야간 배치 작업에 필요한 시스템과 권한만 허용한다. 대화형 로그인이나 목록에 없는 자원 접근은 거부한다.

## 스코어링 결과
- 항목별 점수: MFA 10점, 기기 보안 점검 5점, 최소권한 15점, 세그멘테이션 0점, 위험 기반 인증 0점
- 총점: 30점 / 100점
- 먼저 올릴 항목과 이유: MFA를 먼저 개선한다. 새벽 사건에서 등록되지 않은 기기로 비밀번호만 사용해 정산 내역 120건을 조회했고, 해외 IP 로그인도 성공한 기록이 있기 때문이다. 모든 로그인 경로에 MFA를 적용해 비밀번호 유출로 인한 계정 침해 위험을 줄인다.
