### 문제 2-2 · 접속 요청 여섯 개를 5대 원칙의 칸으로 분류하기

- (가) 요청 ① ~ ⑥ 은 각각 5대 원칙 중 어느 칸에서 걸리나요? 걸리지 않고 통과하면 「통과」라고 적어 주세요.
  - 쓸 내용: 「①: … / ②: … / ③: … / ④: … / ⑤: … / ⑥: …」 여섯 개
  - 답:
  ① ID 칸 — 비밀번호만 사용해서 관리자 권한 접속에 필요한 MFA가 없다.

② Device 칸 — 개인 노트북이고 백신이 꺼져 있으며 보안 패치도 6개월 동안 적용되지 않았다.

③ Application 칸 — 마케팅팀은 인사 시스템을 사용할 권한이 없다.

④ Network 칸 — 서버 구역의 DB에 앱을 거치지 않고 직접 연결하려고 한다.

⑤ Policy 칸 — 해외 IP와 새벽 03시 접속이 평소의 정상적인 접속 패턴과 다르다.

⑥ 통과 — 로그인, 기기, 위치와 시간, 앱 권한에 문제가 없다.
- (나) 🔍 요청 ⑤ 는 ID · Device · Application 이 모두 정상인데 왜 Policy 칸에서 걸리나요?
  - 쓸 내용: ① 정상인 것 ② 평소와 달라진 상황 ③ Policy 칸이 하는 일
  - 답:
  ID 인증과 MFA는 정상이고, 등록된 기기와 앱 권한도 문제가 없다. 하지만 평소에는 서울에서 접속하던 계정이 해외 IP에서 새벽 03시에 접속했다. 따라서 위치와 시간에 따른 위험도가 높아 Policy 칸에서 추가 확인이나 차단이 필요하다.
- (다) 요청 ③ 과 ④ 는 둘 다 가면 안 되는 곳에 닿으려는 시도인데 왜 서로 다른 칸에서 걸리나요?
  - 쓸 내용: ① ③ 이 확인하는 것 ② ④ 가 확인하는 것
  - 답:
  ③은 마케팅팀 사용자에게 인사 시스템을 사용할 권한이 없으므로 Application 칸에서 걸린다. ④는 개발팀 사용자가 앱을 거치지 않고 DB에 직접 연결하려 하므로 Network 칸에서 걸린다. 즉, ③은 앱 사용 권한 문제이고 ④는 네트워크 연결 경로 문제이다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답:
  로그인에 성공했더라도 모든 자원에 접근할 수 있는 것은 아니며, 사용자와 기기뿐 아니라 접속 경로와 시간, 위치까지 확인해야 안전하다는 것을 알게 되었다.

- (나) 🔍 실행해서 나온 요청 A ~ F 의 결정을 적어 주세요. 모두 기대 결정과 같은지도 함께 적어 주세요.
  - 쓸 내용: 「A: … / B: … / C: … / D: … / E: … / F: …」 여섯 개와 「기대 결정과 같음 · 다름」

- (다) 🔍 점수 세 개를 정하면서 찾은 조건을 적어 주세요. 점수 하나가 가질 수 있는 범위와, 두 점수의 합이 만족해야 하는 조건이 있나요?
  - 쓸 내용: ① 기기 보안 상태 이상 점수의 범위 ② MFA 점수와 해외 점수의 범위 ③ 둘의 합이 만족해야 하는 조건과 그 이유(요청 몇 번 때문인지)
  - 답:

- (라) 🔍 기기 보안 상태 이상은 정산 조회에서는 추가확인인데 권한 변경에서는 거부입니다. 왜 기준이 다른가요?
  - 쓸 내용: ① 정산 조회에서 그 신호의 점수와 결정 ② 내가 정한 권한 변경 점수와 결정 ③ 기준이 다른 이유
  - 답:
  정산 내역 조회보다 계정 권한 변경이 더 위험하기 때문이다. 권한 변경은 다른 계정의 접근 권한까지 바꿀 수 있으므로 기기 보안 상태에 문제가 있으면 점수와 관계없이 더 엄격하게 거부하도록 기준을 정했다.

### 문제 3-2 · 요청 7건을 한꺼번에 판정해 건수 세기

- (가) 실행해서 나온 출력 전체를 붙여 넣어 주세요.
  - 쓸 내용: 거부 · 추가확인 줄, 건수 줄, 이유별 건수 줄 전체
  - 답:

[추가확인] 2 seoyeon ['대량 조회 (+30)']
[거부] 3 seoyeon ['이 계정에 등록된 기기가 아님']
[거부] 4 dami ['재직 중인 계정이 아님']
[추가확인] 5 junho ['기기 보안 상태 이상 (+40)']
[거부] 6 junho ['해외에서 접속 (+30)', '새벽 접속 (+20)']
[거부] 7 seoyeon ['이 계정에 등록된 기기가 아님']
허용 1 건 / 추가확인 2 건 / 거부 4 건
거부 이유별 건수 {'이 계정에 등록된 기기가 아님': 2, '재직 중인 계정이 아님': 1, '해외에서 접속 (+30)': 1, '새벽 접속 (+20)': 1}
- (나) 🔍 거부된 요청 중 필수 조건에서 바로 거부된 것과 점수가 쌓여서 거부된 것은 각각 몇 번 요청이고 이유가 무엇인가요?
  - 쓸 내용: ① 필수 조건으로 거부된 요청 번호와 이유 ② 점수로 거부된 요청 번호와 이유 목록
  - 답:
  ① 필수 조건으로 거부된 요청: 3번은 등록되지 않은 기기로 접속했고, 4번은 재직 중인 계정이 아니어서 거부되었다. 7번도 등록되지 않은 기기로 접속하여 거부되었다.

② 점수로 거부된 요청: 6번은 해외 접속으로 30점, 새벽 접속으로 20점이 쌓여 총 50점이 되어 거부되었다.
- (다) 🔍 거부 이유별 건수에서 가장 많은 이유는 무엇이고, 이 숫자는 보안 담당에게 무엇을 알려 주나요?
  - 쓸 내용: ① 가장 많은 이유와 건수 ② 기록으로 확인되는 것과 확인되지 않는 것 ③ 보안 담당이 할 일
  - 답:
  가장 많은 거부 이유는 등록되지 않은 기기로 접속한 경우로 2건이다. 기록을 통해 등록되지 않은 기기의 접속 시도가 두 번 있었다는 것은 확인할 수 있지만, 실제로 같은 사람이 시도했는지, 공격 목적인지는 이 기록만으로 확실히 알 수 없다. 보안 담당은 해당 계정의 접속 기록과 기기 등록 상태를 확인하고, 반복적인 비정상 접속인지 조사해야 한다.
- (라) 🔍 등록 기기 · 국내 · 낮 시간에 MFA 까지 한 같은 계정이 20건 미만 조회를 100번 반복하면 이 코드는 어떻게 판정하나요? 왜 그런지, 이를 막으려면 무엇이 필요한지 적어 주세요.
  - 쓸 내용: ① 100번의 판정 결과 ② 그렇게 판정되는 이유 ③ 막으려면 필요한 것
  - 답:
  ① 100번 모두 허용된다.

② 이 코드는 각 요청을 개별적으로 판정하기 때문이다. 등록된 기기에서 국내 낮 시간에 MFA까지 완료하고 20건 미만을 조회하면, 한 번의 요청만으로는 거부 조건이나 위험 점수 기준을 넘지 않는다. 이전 요청 횟수를 누적해서 확인하지 않는다.
