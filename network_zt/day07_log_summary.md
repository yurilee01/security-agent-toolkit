# 정산 포털 정책 로그 점검 결과

## 결론
- 정책 판단과 실제 앱 응답이 일치하지 않는 사례가 확인되었습니다. 일부 요청은 정책에서 거부했지만 앱에서 통과했고, 정상 요청이 잘못 차단된 사례도 있어 원인 확인이 필요합니다. 현재 기록만으로 계정 도용 여부를 단정할 수는 없습니다.

## 근거
- **정책 로그 점검(3-1):** 요청 101은 정책에서 거부했지만 앱은 200으로 통과했습니다. 요청 108은 추가확인이 필요했지만 앱은 200으로 통과했고, 요청 112는 허용됐지만 앱은 403으로 차단했습니다. 정책 로그에 없는 요청 201은 앱에서 200으로 통과해 우회 가능성을 조사해야 합니다.
- **오탐·미탐 점검(4-1):** 현재 규칙은 오탐 6건, 미탐 0건입니다. 오탐은 정상 요청을 잘못 의심하거나 막은 경우이고, 미탐은 위험 요청을 제대로 거부하지 못한 경우입니다.
- **조정안 비교(4-1):** 안 A는 오탐 0건, 미탐 1건입니다. 안 B와 C는 오탐 0건, 미탐 2건입니다. 안 A에서는 요청 11이 점수 30점으로 추가확인에 그쳐 거부되지 않습니다.

## 권고
- **안 A를 검토하되**, 오탐이 6건에서 0건으로 줄어드는 효과와 미탐이 0건에서 1건으로 늘어나는 위험을 함께 고려합니다. 특히 요청 11처럼 해외 접속 점수만으로 거부 기준에 도달하지 못하는 사례를 추가로 점검합니다.
- 요청 101·108·112·201의 정책 기록과 앱 응답 기록을 대조하고, 정책 판단을 실제 앱에 전달하고 적용하는 과정의 설정과 기록을 확인합니다. 정책 로그에 없는 요청 201은 인증·라우팅·로그 수집 기록 등을 함께 살펴 우회 여부를 확인합니다.
