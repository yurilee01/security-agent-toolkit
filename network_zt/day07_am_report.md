- (가) `cat day07_log_summary.md` 로 본 내용에 결론 · 근거 · 권고가 모두 있나요? 빠진 곳이 있으면 어디인지 적어 주세요.
  - 쓸 내용: 「모두 있음」 또는 「빠진 곳: …」
  - 답:모두 있음. 결론에는 정책 판단과 앱 응답이 일치하지 않는 문제가 있고, 근거에는 3-1과 4-1의 점검 결과가 있으며, 권고에는 안 A 검토와 관련 기록 추가 확인이 적혀 있다.
- (나) 🔍 쓴 근거 세 개는 각각 어느 출력(3-1 · 4-1)에서 가져왔고 어떤 값인가요?
  - 쓸 내용: 「근거 ①: 출력 … / 값 … / 근거 ②: … / 근거 ③: …」
  - 답:근거 ①: 3-1 출력 / 요청 101은 거부인데 앱은 200, 요청 108은 추가확인인데 앱은 200, 요청 112는 허용인데 앱은 403, 요청 201은 정책 로그가 없는데 앱은 200이다.
근거 ②: 4-1 출력 / 현재 규칙은 오탐 6건, 미탐 0건이다.
근거 ③: 4-1 출력 / 안 A는 오탐 0건·미탐 1건, 안 B와 C는 오탐 0건·미탐 2건이다.
- (다) 🔍 결론에서 기록으로 확인하지 못한 것을 어떻게 표현했나요? 단정하지 않으려고 바꾼 말이 있으면 함께 적어 주세요.
  - 쓸 내용: ① 확인하지 못한 것 ② 그것을 표현한 말 ③ 바꾼 말(있으면)
  - 답:계정 도용 여부는 기록만으로 확인할 수 없다. 그래서 「계정이 도용됐다」고 단정하지 않고, 「현재 기록만으로 계정 도용 여부를 단정할 수는 없다」고 표현했다.
- (라) 🔍 문서에서 풀어 쓴 전문용어 세 개를 풀어 쓰기 전과 후로 적어 주세요.
  - 쓸 내용: 「① 용어: … → 쓴 말: … / ② … / ③ …」 오늘의 사례를 넣어서
  - 답:① 오탐 → 정상 요청을 잘못 의심하거나 막은 경우
② 미탐 → 위험 요청을 제대로 거부하지 못한 경우
③ 우회 → 정해진 정책 확인 절차를 거치지 않고 서비스에 접근했을 가능성
④ PEP → 정책에 따른 허용·차단 결정을 실제 서비스에서 적용하는 지점
⑤ 집행 누락 → 정책은 거부했지만 실제 서비스에서는 요청이 통과한 경우

- (마) 🔍 「PDP 는 거부했습니다」라고만 보고하면 왜 충분하지 않은가요?
  - 쓸 내용: ① 정책 로그가 알려 주는 것 ② 알려 주지 못하는 것 ③ 그것을 확인하는 방법
  - 답:정책 로그는 PDP(정책을 판단하는 부분)가 허용·거부·추가확인 중 어떤 결정을 했는지 알려 준다. 하지만 실제 앱이 그 결정을 제대로 적용했는지는 알려 주지 못한다. 요청 101처럼 PDP는 거부했는데 앱은 200으로 통과할 수 있으므로 정책 로그와 앱 응답 기록을 요청 번호별로 대조해야 한다.
- (한 줄) A사 대표에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 대표가 바로 읽을 수 있는 한 문장(점검 결과와 앞으로 할 일)
  - 답:정책 판단과 앱 응답이 다른 사례 4건을 확인했으며, 오탐을 줄이면서 위험 요청을 놓치지 않도록 안 A를 검토하고 관련 정책·앱 기록을 추가 조사하겠습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답:정책에서 거부했다고 해서 실제 앱에서도 반드시 차단된 것은 아니므로, 정책 로그와 앱 응답을 함께 확인하고 점검 결과는 근거와 권고를 포함해 쉬운 말로 보고해야 한다.
